# dual-paraboloid-map

Dual-Paraboloid Map のベイカーと、反射での比較ビューア。
GTA V が環境キューブマップを DP マップ (128×128×2半球) に変換して反射に使っていた手法を、
「本当に有効か」を数値で見るための検証装置として実装したもの。仕様は `dual-paraboloid-spec.md`。

入力は仕様の equirect HDRI ではなく、同梱の Yokohama cubemap (Humus, CC-BY) を使用。
これに伴い 3 経路を次のように定義している。

1. DP map — 焼いた DP マップ 2 枚
2. Cubemap (same res) — 入力を同解像度に焼き直した cubemap。DP と同じ情報量での対抗馬
3. Ground truth — 2048² の入力を直接引く

## 計測について

RMSE は反射体の画素だけを対象に集計する (背景を含めない)。
全経路を明示 LOD 0 で引いており、画面微分による暗黙 LOD は使わない。
暗黙 LOD だと経路ごとに違うミップが選ばれ、「ぼけた真値 vs 鋭い DP」を比べることになって
解像度を上げても誤差が下がらなくなる。

## 測ってわかったこと

Yokohama (輝度が水平寄りに集中) での相対 RMSE:

| 形状 | 解像度 | DP | Cubemap |
|---|---|---|---|
| 球 | 64 | 0.135 | 0.101 |
| 球 | 128 | 0.109 | 0.080 |
| 球 | 256 | 0.089 | 0.059 |
| 上向き平板 | 64 | 0.115 | 0.066 |
| 上向き平板 | 128 | 0.075 | 0.043 |
| 上向き平板 | 256 | 0.049 | 0.029 |

同解像度なら cubemap のほうが一貫して誤差が小さい。DP が有利になったのは
上向き平板で相対的に差が縮まる点だけで、それでも逆転はしない。
seamless cube map filtering が使える現在、シーム回避を動機に DP を選ぶ理由はない。

## 解像度が偏る向き (仕様書の記述は逆)

DP の forward は `s = d.x / (1 - d.z)` で、極座標に直すと `ρ = tan(θ/2)` になる。
つまりステレオ投影と同じで、**軸方向 (マップ中心) が圧縮され、水平 (単位円) が引き伸ばされる**。
立体角あたりのテクセル数は中心で `1/4`、単位円上で `1`。水平のほうが 4 倍細かい。

Lat/long grid を焼くとそのまま見える。中心付近は 10° ごとの緯度線が密集し、
赤い単位円に近づくほど間隔が開く。解像度 64 で反射させると、天頂/天底は格子が
完全に溶けるのに対し、水平付近は格子が残る。

仕様書 §1 / §7-4 は「上下のディテールを保ち横を犠牲にする」「天頂のグリッドが細かく
水平が粗く潰れる」と書いているが、逆。GTA V が DP 軸を上に向けた理由も
「上方向の解像度が上がるから」ではなく、車のボンネットやルーフに映るのが
主に空で、**空はもともと低周波なので粗くても破綻しないから**と読むほうが筋が通る。

`R = 1.0` + ハードスイッチにすると水平線上にシームが出て、`R = 1.15` + `w = 0.12` で消える。

ブレンドは 2 枚とも無条件にサンプルしてから mix する。分岐の中で暗黙 LOD
(画面微分) を使うと非一様制御フローで未定義動作になり、継ぎ目に破線が出る。

## 受け入れ条件

起動時に仕様 §7-1 / §7-2 のテストが走り、結果は console に出る。
相対 RMSE と最大誤差は GUI の "Error vs path B" に出る。
§7-3 の単調減少は Map resolution を 64 → 1024 に上げて relative RMSE が下がることで確認できる。
